# ML 학습 데이터: 정해야 할 것

[ML 학습용 합성 데이터 계획](README_ml-train-plan.md)을 진행하면서 정하지 않은 것을 모았다. 정하면 이 문서에서 해당 항목을 지우고, 결과를 계획 문서와 코드에 반영한다.

- 지금 상태(2026-10-25): 계획의 2단계(생성기 `ml_train_build.py`, `value_gen.py`)까지 끝났다. 3단계(카드 추첨기, LLM 템플릿 작성 스크립트)는 1절의 답을 기다린다.

## 1. 모델 쪽에서 정할 것

학습할 모델의 형태가 정해져야 템플릿 길이, 채널 구성, 정답을 학습 표적으로 바꾸는 방식이 정해진다. 모델 담당이 아직 정하지 않았다.

| 질문 | 데이터에 주는 영향 | 정하기 전까지 |
|---|---|---|
| 입출력 형식: item 하나를 넣고 span(시작, 끝, 유형)을 출력하는가, 토큰마다 태그를 붙이는가(BIO 등) | 정답 span을 학습 표적으로 바꾸는 변환기가 달라진다. 토큰 분류라면 LABELING.md의 경계(따옴표 안쪽, `Bearer ` 제외 등)를 토크나이저 경계에 맞춰야 하고, 경계가 토큰 중간에 걸리는 경우를 따로 다뤄야 한다 | 데이터는 지금처럼 글자 좌표 span으로 만든다. 어느 쪽으로든 바꿀 수 있다 |
| 모델이 같은 세션의 앞 item을 함께 보는가 | 퍼뜨림 기준(LABELING.md)은 세션 단위다. 앞에서 자격증명 자리에 나온 고유한 값은 뒤의 로그나 오류 메시지에 다시 나와도 정답이다. 모델이 item 하나만 보면 그 등장을 정답으로 판단할 근거가 텍스트에 없으므로, 학습 표적에서 빼거나 앞 item 일부를 문맥으로 붙여야 한다 | 세션 안의 반복 등장(계획 3.3절의 목표: 여러 item 30%, 여러 채널 20%)은 그대로 만든다 |
| 목표 모델 크기와 컨텍스트 길이 | 긴 tool_output을 자를 창의 크기와 생성할 item 길이 분포(계획 3.1절: tool_output 중앙값 500~800자, 10%는 3,000자 이상)가 정해진다. 학습 토큰 수와 LLM 생성 비용도 이것에 따라 바뀐다 | 길이 분포는 실제 트래픽 집계에 맞춘 계획값을 쓴다 |
| tool_input을 학습에 넣는가 | metric-detection은 tool_input을 채점하지 않지만 정답은 같은 기준으로 만들어 둔다. 넣지 않으면 정답의 12%분(계획 3.3절) 템플릿 설계를 줄일 수 있다 | 계획대로 만든다. 학습에서 뺄 때는 채널로 거르면 된다 |
| privesc 상한(train 정답의 30%)이 적당한가 | privesc는 정답이 많지만 리눅스 권한 상승 한 분야라, 많이 넣으면 비밀번호 학습량은 늘고 분야 편향도 커진다 | 30%로 둔다 |

## 2. 파일럿 실행 승인

계획 4단계: LLM으로 템플릿 100개를 써서 300세션을 만들고, 자동 검사, 사람 검토 100세션, 비용 실측을 한다.

| 정할 것 | 지금 안 |
|---|---|
| 실행 승인 | 템플릿 100개, Claude Opus 5.5 Batch로 약 $6(추정, 계획 7절) |
| 생성 모델 | 학습용은 Opus 5.5, 분포 이동 test는 다른 모델(Sonnet 5.5) |
| API 키와 과금 계정 | 정하지 않았다 |
| 사람 검토자 | 2명이 100세션을 본다(1인당 약 3시간) |

3단계 스크립트(카드 추첨기, LLM 템플릿 작성)는 1절이 정해진 뒤 만든다. 템플릿 길이와 채널 구성이 1절에 달려 있기 때문이다.

## 3. LABELING.md와 label_rules가 어긋나는 곳

학습 데이터는 `label_rules`가 정답으로 읽는 값만 만든다. 아래 둘은 LABELING.md 원칙과 `label_rules` 구현이 다르거나 기준이 비어 있어, 정할 때까지 생성하지 않는다.

| 항목 | 내용 | 선택지 |
|---|---|---|
| 공백으로 이은 패스프레이즈 (`correct horse battery staple`) | 원칙("자격증명 자리에 들어간 리터럴")으로는 정답이다. 그런데 `label_rules.is_phrase`가 흔한 영어 단어 여럿이 공백으로 이어진 값을 `descriptor`(`new password` 같은 설명 문구)로 읽어 정답에서 뺀다 | (a) `is_phrase`가 자격증명 자리(`passphrase:` 등)의 값은 문구로 보지 않게 고친다. (b) 지금처럼 생성하지 않는다. 생성기는 `-`, `_`, `.`로 잇거나 붙인 패스프레이즈만 만든다 |
| PuTTY 개인키 (`PuTTY-User-Key-File-3:` 블록) | LABELING.md "경계"에는 PEM 형식(BEGIN 줄부터 END 줄까지)만 있다. PuTTY 형식은 머리글, 공개 부분, 개인 부분, MAC이 여러 줄로 이어진다 | (a) 블록 전체, (b) `Private-Lines:` 아래 본문만, (c) 다루지 않는다 |

## 4. 기존 v2 템플릿의 두 정답

평가 데이터 `sessions_2`(에이전트 세션 v2)의 정답 두 개가 `dataset_verify`는 통과하지만, 학습 데이터용으로 더 엄격하게 만든 자리 검사(`ml_train_build.py verify`)에는 걸린다. 고치면 sessions_2의 정답이 바뀐다.

| 세션 | 지금 정답 | 문제 | 고치는 방법 |
|---|---|---|---|
| `v2-nl-03-wiki` | 웹훅 URL `https://hooks.example.invalid/hooks/⟦토큰⟧`의 경로 끝 토큰 | LABELING.md는 웹훅처럼 자격증명 자체인 URL이면 URL 전체를 정답으로 본다 | 템플릿의 placeholder가 URL 전체를 덮게 한다(type SECRET) |
| `v2-weak-01-conftest` | `os.environ.get("ADMIN_PASSWORD", "admin")`의 `admin` | 원칙상 정답(기본값으로 넣은 비밀번호 리터럴)이지만, `label_rules`에 이 자리 규칙이 없어 흔한 값 `admin`이 자격증명 자리 밖으로 읽힌다 | `label_rules.SLOT`에 환경변수 기본값 자리(`getenv("…PASSWORD…", "⟦값⟧")`)를 더한다. 정답은 그대로다 |
