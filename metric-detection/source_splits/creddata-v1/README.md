# CredData 원본 분할 v1

작업 지시문을 작성하기 전에 고정한 원본 저장소·세션 분할이다. 코드 본문과 비밀값은 포함하지 않으며 기존 평가 파일·학습 허용 정책은 바꾸지 않는다.

| split | 저장소 | 파일/세션 | item | 양성 item | 정답 span |
|---|---:|---:|---:|---:|---:|
| train | 269 | 8790 | 20162 | 4633 | 14036 |
| val | 34 | 1133 | 2581 | 745 | 1492 |
| test | 34 | 1107 | 2602 | 726 | 1498 |

## 사용 순서

1. `repositories.jsonl`에서 원본 저장소의 split과 component_id를 찾는다. 각 `train.txt`, `val.txt`, `test.txt`는 현재 변환본의 session_id 목록이다.
2. 해당 원본으로 작업 환경과 지시문을 작성한다. 원본 저장소→작업→실행→증강본에 source_repo_id, source_session_id, component_id, split을 전달한다.
3. 새로 구성한 실행 가능한 환경은 코드 조각 기반 합성 환경임을 표시한다. 원본 전체 저장소를 복구하면 같은 RepoID를 유지하고 중복 검사를 다시 한다.
4. 실행 전 비밀값을 split별 시드로 치환한다. 궤적·증강을 만든 뒤 임의로 다시 분할하지 않는다.
5. 근접 중복 코드·공유 작업 원형, 미라벨 비밀, 라이선스를 검토하고 원본 출처별 용도 정책을 명시한 별도 학습 데이터 export를 만든다. 이 목록 자체는 학습용 데이터가 아니다.

## 분할 방식

목표는 train/val/test 80/10/10이다. 저장소를 쪼개지 않고 파일 수·item 수·양성/음성·5개 정답 유형의 분포를 함께 고려하므로 실제 비율은 달라진다. 정답을 가린 뒤 남은 비공백 문맥이 160자 이상인 item이 공백 정규화 후 같으면 관련 저장소를 하나의 component로 묶는다. 짧은 코드·근접 중복까지 없다는 뜻은 아니다.

## 검증과 재현

저장소 루트에서 실행한다.

```bash
python3 metric-detection/scripts/split_creddata.py build
python3 metric-detection/scripts/split_creddata.py verify
```

입력 파일 SHA-256, 고정 시드, 분할·검사 통계는 manifest.json에 있다. 같은 입력은 바이트 단위로 같은 결과를 만든다. 다른 입력으로 기존 분할을 덮어쓰지 않는다.

## 해석 제한

- 현재 원본은 파일 주변 창이다. 작업 가능한 전체 저장소는 현재 로컬에 없다.
- 현재 정답은 원래 CredData T/F/X가 아니라 프로젝트 LABELING.md로 변환한 라벨이다. 미라벨 비밀까지 완전하게 주석 처리됐다는 보장은 없다.
- 정답 값 자체의 분할 간 재등장이 남아 있으므로 실행 전 split별 값 치환이 필수다.
- 기존 CredData 전체 평가는 보존됐지만 이 원본으로 학습한 모델의 독립 평가로 사용할 수 없다. 후속 평가는 고정 test 원본과 별도 외부 평가에서 수행한다.
- 기존 평가 데이터는 이미 조사·사용된 자료다. 이 분할을 완전히 미공개인 blind test로 주장하지 않는다.
